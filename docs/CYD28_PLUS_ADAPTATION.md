# ESP32-2432S028R Plus 本地适配

**当前源码：0.1.0-cyd28-dev5t5，诊断版本。FMO 保持 dev5 输出；Plus 扬声器测试改为 5 秒 RC 时钟硬件余弦（GPIO26、最低 1/8 幅度），绕过 PCM/DMA/APLL。静音或零音量不播放；测试过程中静音会提前停止。非零软件音量不改变硬件测试幅度。用户确认关闭背光及恒高停止PWM时均无劈声；dev5t4将Plus背光改为无PWM亮灭两档，保留熄屏/唤醒。具体电路耦合路径未测量。**

2026-11-23，开发版本 `0.1.0-cyd28-dev5t5`，板型 ID `esp32-2432s028r-plus`。

用户实物照片确认白色 PCB 丝印 ESP32-2432S028R Plus、ESP32-WROOM-32E、CH340C。早期按 LCDWIKI E32R28T 的假设已经撤销；未刷入早期 ILI9341 候选。此实现仅针对 Plus，不能据此宣称 E32R28T 或普通黄色 CYD 已适配。用户授权离线测试通过后刷入本机新板，不公开发布、不做真实 SSTV 发射。

## 硬件依据

- [厂商 Plus 产品页面](https://www.zlxchina.com/zh/product/esp32-2432s028r-plus-development-board)：ST7789 / XPT2046、BGR、240×320。
- [厂商引脚及极性定义](https://github.com/qmaakdfq/ESP32-WROOM-32E-UE-Module-Development-Board/blob/main/08_Audio_PWM_and_Amplifier_Test/include/pins.h)：GPIO26 音频、该通用PWM示例将GPIO4标记为高有效，但与同仓库Plus音频专用示例矛盾，dev5已撤销此依据。网页表中 AUDIO_IN 名称不表示板载麦克风，源码明确作为输出。
- [厂商显示配置](https://github.com/qmaakdfq/ESP32-WROOM-32E-UE-Module-Development-Board/blob/main/01_ST7789_Display_Test/src/main.cpp)：横屏、BGR、不反色。

本地实现 LCD 使用 SPI2（14/13/12/15/DC2）、背光21 PWM；触摸使用 SPI3（25/32/39/33/IRQ36）。当前 TF 完全关闭，因此不需要第三个 SPI 控制器。DAC 输出26，GPIO4低电平开启8002B，保留 I2S 音频时序与 FMO 下行解码。GPIO34 电池未做校准，显示未知电量；RGB 只关闭，不承诺颜色顺序。麦克风未安装，底层 PTT、测试和采样请求均禁止。

## 用户操作

首次启动按屏幕三个 `+` 依次稳定按住并松开，校准结果保存在独立 NVS namespace。误点导致退化坐标会要求重做。菜单 `Touch calibration` 可重新校准。

横屏底栏：主页 Menu / Relay / Album / Volume；其他页面 Prev / OK / Next / Back。短于60ms、跨按钮、明显拖动及熄屏唤醒首触不执行菜单动作。Back 返回主页。菜单支持身份体系、网页配网、扬声器测试、资源容量和 SSTV RX。无麦克风 PTT，无旋转或物理按键重映射入口。首版底栏及校准提示为英文。

设备网页使用内部相册，不显示 TF 管理；实际容量来自存储统计。新设备自行生成密钥，复用现有多 CA 与证书流程；不从其他设备复制身份。

## 4MB 与内存预算

| 区域 | 起点 | 大小 |
|---|---:|---:|
| NVS | 0x9000 | 0x6000 / 24 KiB |
| PHY | 0xF000 | 0x1000 / 4 KiB |
| 单应用 | 0x10000 | 0x310000 / 3136 KiB |
| 内部 SPIFFS 相册 | 0x320000 | 0xE0000 / 896 KiB |

末地址0x400000，无双槽 OTA。网页和字体嵌入应用，没有额外资源分区。相册采用 70% 保守安全水位（同时不超过 SPIFFS 报告总量）；实际可用量考虑元数据、缩略图与临时文件，不承诺固定张数。满空间拒绝新导入，已有图片保留。原有或损坏分区不自动格式化，只有全FF空白分区才初始化。

LCD 单个4行缓冲2560字节；图片使用两行 RGB565 流式读写及小预览，不分配153600字节整图。无 PSRAM 配置。静态链接余量不是运行时堆余量，后者必须在真机 Wi-Fi、音频和相册并用时记录。

## SSTV 边界

已有：Robot36 编码、解码、流式图像存储、网页上传导出与相册查看、网络下行音频接收链路；沿用离线编解码和存储回归。

当前禁止：Plus 开发版网络 SSTV 发送（底层拒绝、网页按钮禁用、触屏无发送入口）、麦克风采集和语音 PTT。保留 USB 本地编码 probe（不 publish）与编码器接口供后续扩展。没有做 RF 发射或服务器播放，没有宣称 MAX9814 已兼容。

## dev5 SPK无声修复（2026-11-23）

用户反馈音量100%、SPK连接喇叭但FMO和本地扬声器测试均无声。刷前USB实测voiceConnected=true，rxPackets154、decodedFrames504、decodedSamples/pcmSamplesWritten291840、decodeErrors/outputErrors均0、muted=false。此证据证明数据链路已处理音频，不等于模拟输出已验证。

进一步核对[厂商Plus专用蓝牙音频源码](https://github.com/qmaakdfq/ESP32-WROOM-32E-UE-Module-Development-Board/blob/main/ESP32-2432S028R-PLUS%20Audio%20Test%20demo%20Example%20Bluetooth%29/src/main.cpp)：AUDIO_EN=4、AUDIO_EN_LEVEL=LOW，注释LOW打开8002B；GPIO26/DAC2。之前采用08通用PWM示例的AMP_EN_ACTIVE_HIGH=true造成GPIO4设反。dev5保持GPIO4低电平，仅修正Plus外围初始化。IDF源码亦确认I2S_DAC_CHANNEL_LEFT_EN对应DAC2，左右声道均填入同一PCM，未更改DAC路径。

新增test_cyd28_audio.py运行真实外围初始化，检查GPIO4低有效、RGB关闭、后续状态更新不改功放、不占用DAC26；Plus触摸/存储/直接路由及RX解码回归通过，构建通过。实际听感需刷后由用户确认；不得提前标记SPK通过。

## dev6 输出时序验证版

用户确认dev5已能出声，但无论音量大小，播放期间及本地提示音均有劈声。因此不能只归因为网络抖动或大音量削顶。dev6针对已经从源码确认的DAC初始化与功放时序缺口：开机功放先静音，DAC六块DMA缓冲填0x8000中点，等待120ms后GPIO4拉低开功放；关闭DAC前先静音功放，初始化写入失败保持静音。Plus空闲继续输送中点静音，不每两秒关DAC；M5/小智保持原逻辑。会常驻DMA缓冲，须检查实际堆余量。

Plus菜单测试音由0.4秒800Hz方波改为2秒500Hz正弦，幅度1800、首尾20ms线性包络，便于听感诊断。仅本地扬声器输出，不向服务器发送。时序和包络专项测试覆盖真实初始化函数、六块中点、等待、短写/错误静音、波形边界/幅度/连续性。

本版是针对输出链路的诊断修正，不宣称已确定或消除持续劈声；需用户对比平滑提示音与FMO语音。若仍有持续噪声，继续分离DAC/功放供电和喇叭硬件因素，不能仅凭零输出错误判定听感正常。

## dev7 GPIO26模拟引脚初始化

用户明确反馈dev6音质仍非常差、持续劈声不受音量影响，dev6听感改善验收失败。检查当前ESP-IDF v5.5.1本地源码：driver/deprecated/i2s_legacy.c的i2s_set_dac_mode只调用dac_ll_power_on和DMA开关；driver/deprecated/dac_common_legacy.c的dac_output_enable才调用dac_rtc_pad_init/gpio_config_as_analog清除数字输入输出和上下拉。现有Plus路径此前遗漏该步骤。

dev7仅在Plus启用I2S DAC前调用dac_output_enable(DAC_CHAN_1)，对应GPIO26/DAC2；失败则不启用输出，保留dev6静音预填和时序。测试执行真实封装验证顺序和错误传播。该代码缺口已确定，但持续劈声的因果尚未实物确认；已请求喇叭阻抗/功率、USB供电及替换喇叭条件，硬件信息仍待补充。

## dev8 专用连续DAC输出（构建完成，尚未刷入）

### dev5t2 音频排查依据

- 4Ω 3W、8Ω 1W、替换单元及电池供电均被用户报告仍劈声，不能将根因认定为阻抗。
- dev5/6/7 的 legacy I2S 与 dev8/9 的 dac_continuous 都使用 APLL；改驱动没有独立排除这一共同路径。
- Espressif 历史问题 https://github.com/espressif/arduino-esp32/issues/8467 记录类似 DAC 劈声及 APLL 相关对照。其版本不同，不能直接套用结论。
- 当前 IDF5.5.1 legacy 驱动 8kHz/16bit DAC 时钟要求使简单 use_apll=false 导致主时钟分频越限，因此未盲目更改该开关。
- dev5t2 使用当前 IDF 提供的 dac_cw_generator_* 旧版 API，与现有驱动一致，避免混入新旧驱动冲突。由 audio task 独占切换，退出时停止生成器并写128解除余弦通道，下一次 FMO 恢复原I2S。未启用 DAC1/GPIO25 的输出。
- 测试音干净会支持进一步排查数字路径；测试音仍劈声只能说明独立硬件音源下亦复现，仍需评估板载模拟链路、共用资源或测量证据。测试音音色/幅度不同，不作定量音质比较。
