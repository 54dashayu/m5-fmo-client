# SSTV 发射与 M5 TF 相册 · 0.7.72-dev

基于 0.7.71 的本地开发候选，未发布、未刷入设备，尚未进行真实中继发射或 TF 卡实测。M5 FIRE 类与小智共用 Robot36 发射逻辑，TF 后端仅用于 M5。

## 使用方式

1. M5 关机后插入 FAT32 TF 卡，再开机。挂载成功后相册显示“TF 卡”；无卡或挂载失败时使用内部 Flash 相册。固件不格式化 TF 卡。
2. 在设备局域网管理网页打开“SSTV 相册”，选择本地图片，点击“保存到设备相册”。浏览器按比例缩放并补黑边到 320×240，不裁掉画面。
3. 退出设备的 SSTV 接收模式，确认已经接入目标 FMO 中继、频道空闲。选择图片的“发送 Robot36”并确认，发送约 37 秒。
4. 网页显示进度并提供停止按钮；设备的 PTT 停止动作也会中止 SSTV。关闭浏览器不会中止已开始的发送。完成仅表示音频包已交给本机传输层，不代表远端成功收图。

首版通过网页导入图片，不直接扫描 TF 卡上的任意 JPG/PNG 文件。图片保存在卡的 `fmo-sstv` 目录，采用带 CRC 的设备相册格式；可在网页查看、导出和删除。导入与接收存储共用相册。

## 存储行为

- M5 使用已有 LCD SPI 总线：SCK 18、MOSI 23、MISO 19、TF CS 4；SD 运行在 10 MHz。引脚依据 [M5Stack FIRE 官方 microSD 文档](https://docs.m5stack.com/en/arduino/m5fire/microsd)。
- TF 卡按剩余容量保存，移除原 20 张保存上限；网页每页 20 张，设备 A/C 跨页浏览，每次只缓存 20 条索引。
- 容量统计使用 64 位，整张卡的其他文件也计入已用空间，保留至少 1 MiB 余量。剩余可保存张数是估算，不是容量保证。
- Flash 相册继续保留原 20 张上限。插卡不会迁移、删除或覆盖 Flash 旧图；关机拔卡再启动可重新访问内部相册。
- 本版只在开机挂载，插拔前必须关机。热插拔、exFAT、不同容量与品牌卡尚未验证。建议首轮使用已有的 FAT32 卡进行测试。
- TF 不可读时回落到 Flash；请以网页显示的存储介质为准。卡内其他目录不受修改。

## 编码与发送

- Robot36，VIS 0x08（加偶校验后的线码 0x88），8 kHz 单声道、320×240；每行 150 ms，包含 9 ms 同步、3 ms porch、88 ms Y、4.5 ms separator、1.5 ms porch、44 ms chroma。
- 逐行读取并连续相位生成音频，经现有 RADPCM / FMO 打包，每包 80 ms；整帧 463 包，约 37.04 秒，包含尾部静音。
- M5 不分配完整 RGB565 帧，发射复用音频任务的发送队列。小智 JPEG 相册在发射准备时解码到帧缓冲。
- 发送前校验图片 CRC；未接入、收话、收图、麦克风测试、已有发射或待发包时拒绝开始。
- 断线、手动停止、读取失败或队列丢包会中止，清理未提交的本地队列；已进入网络传输层的音频不能撤回。不添加语音双音尾音。
- 网页导入需要登录、固定长度数据和空闲状态；采用临时文件、校验和、刷盘后重命名，失败不生成相册条目。整个上传限制约 20 秒（单次网络读取还受 HTTP 超时限制）。

## 本地验证

- 双板 ESP-IDF 构建：M5 ESP32 与小智 ESP32-S3。
- `tools/run_tests.py`：完整离线回归，含新增编码器、发射状态机及存储测试。
- Robot36 编码 → PCM / RADPCM → 现有解码器：240 行完整恢复，验证彩条、VIS、总时长、结束及读取错误。
- 实际发送状态机离线测试：463 包、计数器连续性、重复/忙碌拒绝、主动停止、断线、拥堵、无图片和损坏读取。
- 实际存储测试：导入、逐行一致性、中断、CRC 拒绝、45 张图片双向分页；挂载测试验证 TF 优先及不自动格式化。
- Playwright + 本地模拟接口：登录、导入 153600 字节图片、发送指定 ID、进度、停止、分页及手机宽度布局。模拟页面没有连接真实设备或中继。
