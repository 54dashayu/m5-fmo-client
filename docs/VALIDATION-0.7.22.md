# 0.7.22-dev 验证记录

本记录保留开发阶段的实测证据及其边界。用户已授权发布 0.7.22 正式版；正式构建仅移除 dev 版本标识，下面列出的哈希属于实测开发构建，正式产物哈希见发布包 SHA256SUMS。

## 已实现

- 每台设备固定八位数字管理码；普通重启、保留配置升级不更换。更换使用者的可重放身份事务会清除旧管理码和浏览器授权。
- 记住浏览器、跨重启登录、退出撤销授权；四个浏览器授权槽。
- 设备中继菜单和网页从已验签 APRS 目录发现节点，使用本机证书逐个认证，不发送或订阅语音。成功结果绑定当前身份、服务器端点和证书指纹。
- 移除按“西南集群”名称判定信任的逻辑。名称来自验签广播。收藏满时允许临时接入，不覆盖收藏。
- 发现页显示后台进度；普通网页只查询展示字段，完整诊断保留在 USB。目录解析与管理 API 共享分配锁，避免同时产生大型 JSON 对象；认证包转移解析对象所有权，避免复制整条证书链。USB 请求缓冲从 256 字节按需增长至 8193 字节，仍完整支持 8192 字节请求，平时释放约 8 KB。

- 固件写入后 esptool 哈希校验通过；本次应用 SHA256：
  `97576dba8f97f7e5aaea335c2117a4537591ca92e40c2ff21f65a799143a86f0`
- 记住登录曾实测跨硬件重启有效、退出后返回 401。固定管理码的重启保留与删除后重新生成已通过提取实际启动代码的主机测试。
- 最新固件已重新认证接入绵阳节点，音频初始化完成。此前开发构建曾在保持测试台连接时实际认证发现 UID 730；不能把这个结果推断为所有西南节点均接纳 M5。

## 尚有限制

- 目录每批最多六个近期候选，设备缓存容量八个；公共 APRS 汇总及候选批次不保证覆盖全网。
- 独立根 CA 只有根文件还不够，需要有效的公开中间证书才能验证广播。目前目录可用中间签发者只有官方 1001 和本机 M5 签发者；其余缺链记录跳过，不能根据名称放行。
- 不主动拉取服务器证书 CRL；对本机设备的接入与吊销由对方 SAS 决定。短认证通过也不等于已经人工验收双向通话质量。
- ESP32 无 PSRAM 配置的堆余量仍偏低；当前只是短时运行观察，不代表长期稳定性或收发压力验收完成。
- 部署的目录服务只读公共广播和已启用根证书；未重启 SAS/EMQX，也未修改语音服务。
