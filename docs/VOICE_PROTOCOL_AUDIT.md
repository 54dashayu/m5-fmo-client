# 上行语音协议核对（2026-11-09）

依据：[BG5ESN FMO 语音数据开放协议](https://bg5esn.com/docs/fmo-voice-codec-spec/)。核对对象为设备上运行的 0.7.14；0.7.15 时间戳候选已撤出稳定版源码，不参与发布。

| 项目 | 当前实现 / 结论 |
| --- | --- |
| 音频参数 | 8kHz、单声道、16-bit，RADPCM 每帧640样本/80ms |
| 消息及帧尺寸 | 消息头64B，传输头8B，编码头8B，RADPCM328B；单帧消息408B |
| RADPCM恢复点 | 编码前的predictor/step；序号0起递增，长度16-bit 320 |
| IMA核心 | 步长表、索引表、限幅、高nibble优先与独立audioop结果一致 |
| 连续解码 | 新增140帧测试：连续状态、主动丢帧恢复及uint16回绕均与独立解码器逐样本相同 |
| CRC32 | 仅帧区，独立zlib检查一致 |
| vendor | 0x1791，规范实验区 |
| 传输帧index | 本实现包内1起；文本未明确跨包作用域，不凭猜测改为全流编号 |
| timestamp | 0.7.14按采样序号推算；规范要求包生成UTC。0.7.15候选曾尝试组包时读取UTC，未确认是断续根因。稳定版按用户要求保留0.7.14已验收行为 |
| 输入滤波 | 当前约80Hz高通及软限幅，不同于规范DC抑制示例约1.3Hz；规范允许额外滤波。可能影响音色，尚无证据表明造成缺帧 |

独立测试只能验证已知PCM的编码正确性，不能证明真实麦克风输入正常，也不能证明服务器或接收端收到完整消息。用户报告官方FMO及其他客户端均断续，因此准备在自有测试台采集一次用户主动发送的上行，检查实际帧序号、恢复点连续性、收包间隔及解码回放。

采集工具只订阅，过滤本机实验vendor及BH1JSS呼号，限制单一语音流/200包，超时240秒；不发布语音。实际录音和诊断保存在临时/忽略目录，不进入GitHub。

## 实际上行采样

用户在自有测试台主动发话一次：收到108包、解码8.64秒，缺帧0、跨帧恢复点不一致0、格式/CRC错误0。到包间隔中位78.83ms、最大137.60ms，6次超过120ms，无超过200ms。这证明该样本已完整到达自有服务器，不代表西南集群路径或接收端播放一定正常。提供未补音/未降噪的服务器原始解码回放，用户比较后确认没有明显卡顿、通话质量可接受，仍有少量噪声。设备仍为0.7.14，未把时间戳候选当作已验证修复。
