# 0.7.25-dev 接收缓冲验证

目的：保持 8 kHz 播放，改善短 Opus 包的突发接收溢出。未更改上行编码、证书或服务器信任策略。

旧实现用四个 1400 字节固定包位，启动固定等待 240 毫秒。新实现使用 5120 字节环形字节缓冲和最多 24 个描述符，仅保存实际包长；总结构不超过原四包内存预算。容量仍有限，满时淘汰最早包并统计；不会无限积压。

启动缓存按帧样本数计算：达到 240 毫秒语音、接近空间上限、或等待超过 240 毫秒即播放；一个接收会话只预缓冲一次。Opus 样本数读取包头，不增加解码遍数。接收等待仍有 40 毫秒上限。

离线验证：真实缓冲实现通过 20000 次随机环回/容量压力操作与独立 FIFO 模型对照，检查字节、样本时长、顺序及丢弃数量；覆盖 12 个短包不丢弃、预缓存边界、清空和非法包。完整主机回归与 ESP-IDF 构建通过。

此记录保留开发构建实测；用户已授权以同功能构建发布 0.7.25 正式版。
