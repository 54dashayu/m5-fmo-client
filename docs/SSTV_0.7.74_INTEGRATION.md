# SSTV 与 0.7.74 合并说明

合并基线：`v0.7.74`（`262db50dcb6053f863815aed88304b9f1828156d`）。合并开发版本：`0.7.75-dev.19`。本分支包含本轮 Robot36 发射、相册与 M5 TF 卡改动，并正式合入 0.7.74 的站点/网格定位、本机身份界面、发布说明和打包配置。公开稳定版仍为 0.7.74，按用户要求仅提交在线刷写测试入口，不推送 GitHub、不覆盖原标签；不宣称通过 GitHub 正式版发布门禁。

## 板型差异

| 功能 | M5 | 小智 ESP32-S3 |
| --- | --- | --- |
| FMO 中继 Robot36 发射 | 支持 | 支持 |
| 网页裁剪、320×240 导入、上传进度和自动刷新 | 支持 | 支持 |
| 设备相册选图、发射确认 | 支持 | 支持 |
| 内部相册 | 支持 | 唯一存储介质，最多 20 张 |
| TF 卡选择、检测、格式化 | 支持 | 不显示入口，不注册对应 HTTP 路由；USB 操作返回不支持 |
| 三图横向预览 | 中间 120×90、两侧 80×60；固定 7200 字节缓冲及派生缓存 | 相同焦点/按键逻辑；复用 PSRAM 缓冲，窄屏裁切侧图外缘 |

小智构建不依赖 M5 的 FATFS/SDMMC 驱动；共享存储接口保留无硬件实现。网页按板型构建：小智没有 TF 卡管理 DOM，不发送卡状态请求；M5 单独嵌入 TF 控件片段。

## 验证

- 两板固件构建通过，应用均适配现有分区。
- 完整离线回归通过，含 0.7.74 身份/站点/网格功能及 SSTV 编码、相册、卡任务、预览缓存和按键流程。
- 小智不支持 TF 时，卡操作拒绝且不改变存储选择/执行卡任务。
- 浏览器使用实际生成的小智页面和模拟接口：相册、裁剪上传、发射入口保留；无 TF 控件、无卡管理请求、无页面脚本错误。两板生成 HTML 的能力差异检查通过。
- 构建产物保存于父目录 `output/sstv-074-integration-dev19/`，附 SHA-256 和源码提交信息。这里的 `.bin` 为应用分区镜像，不是整片擦写包。

## dev.20 页内裁剪与上传提示

选择图片后自动在相册页内展开 4:3 裁剪区域，支持拖动、缩放、完整画面、重置和取消；点击保存才上传。切换文件会释放旧位图，异步加载只保留最后一次选择；上传中禁用编辑，成功后收起预览，失败保留裁剪并隐藏上传进度条。接收模式开启时明确要求退出接收页，不再误称正在通联/收图。两板共同代码，版本一致。完整离线回归、两板构建及浏览器模拟上传流程/手机布局验证通过。

## dev.21/dev.22 M5 接收内存与看门狗修复

M5 dev.20 实机接收初始化返回 init_error=1，内部空闲约 11 KB、最大连续块 4096 字节，无法分配约 6.6 KB 解码器及 10800 字节预览。dev.21 将接收解码器/80×60 预览与三图相册共用 11624 字节静态 union，用原子所有权避免 USB 初始化与相册互相覆盖；互斥锁也改为静态分配。接收保存仍为 320×240 RGB565，两板发射编码未改变。主机测试在接收模块 calloc 全部失败条件下验证初始化、退出、相册覆盖工作区后重新初始化和收流。

dev.19 原始看门狗地址通过重建同提交 ELF 解码；重建镜像三个可执行段与已刷 dev.19 完全一致。栈为 lv_mem_buf_get → circ_calc_aa4/lv_draw_mask_radius_init → draw_bg → LVGL 刷新，圆角遮罩分配失败进入断言。M5 面板和徽标使用直角避开此分配；小智保留圆角。没有关闭断言或延长看门狗超时。

完整离线回归及 M5/小智双板编译通过。M5 已仅刷写 0x10000 应用分区并通过镜像校验；启动报告 dev.21、音频就绪，TF 相册原有图片 #1、#2、#3 仍在。小智仅构建，当前设备和公网刷写页仍为 dev.20。本次尚未进行 RF 发射或实际收图，不能据此宣称长期稳定。

继续观察 dev.21 时发现中继握手期间内部空闲内存降至约 3 KB，且 MQTT 尚未恢复，不能视为修复验收通过。dev.22 将 M5 解码器每行频率缓存从 float 改为 int16_t（解调输入范围 ±4000 Hz，量化误差小于 1 Hz），接收预览改为 64×48 RGB332。最终 ESP32 工作区为 7616 字节，比原相册 7200 字节多 416 字节；相册预览尺寸不变，保存仍为 320×240。全帧 PCM/RADPCM、色条、奇偶亮度行、VIS 校验、中断检查、实际预览绘制及完整离线回归通过；两板编译通过。dev.22 实机已恢复 Wi-Fi/中继连接及音频，USB 接收预初始化返回 ready=true、init_error=0，约 40 秒连续采样未出现新的看门狗；相册原有 3 张图片仍在。另补齐从主页直接进入相册时释放诊断预初始化工作区，并以生产页面切换分支做回归。用户随后确认 dev.22 接收页与相册来回切换正常；接收整图仍待实测。

## dev.23/dev.24 #3 发射读取超时排查

用户从 M5 硬件相册发射 #3，dev.22 实机在 16%、6.363 秒结束：sstv_timing_overrun，76 帧生成/提交、零队列丢帧，最长读行 358602 µs，最长编码 360611 µs，最大超时 283406 µs；当时中继在线，无新看门狗。相同图片无发射 probe 在 55% 复现读行 386861 µs。dev.23 避免顺序逐行读取时重复 fseek，但无发射复测仍在 18% 出现读行 337326 µs，因此该优化单独不能解决问题。另一次 probe 因 No PING_RESP 断开中继结束，与读超时分别记录。

dev.24 将原小智首页的按需更新助手用于 M5，并让发射页提前独立刷新，避免先重写通用页脚再覆盖发射提示。相同内容不反复分配/重绘，仍每 150 ms 检查进度，按键检查节奏不变。真实 LVGL 主机测试验证 100 次不变进度刷新零新增像素传输，进度变化仅局部重绘；连续/跳转/重复图片行读取回归通过，双板构建和完整离线回归通过。未放宽 160 ms 发送超时阈值。实机 probe 与最终验收结果另记。


dev.24 实机无发射 probe 仍在 47% 出现 358564 µs 的读延迟并超时，界面优化不是完整修复。dev.25 因此改用 11 行预读：复用原 7616 字节 workspace 中 7040 字节，发射前完成校验和首批缓存，现有管理任务每 5 ms 检查并补入一行，音频任务按序从环形缓存取行。读卡与定时编码解耦，无新增整图堆内存、任务或栈。停止时先撤销生产者指针，并等待正在进行的读操作结束，再释放文件和工作区。网页在 M5 相册页发起时自动退回主页释放预览工作区，此路径不调用会取消 PTT 的页面切换函数。预读失败/耗尽仍终止发送，不延长超时或跳过图像数据。

真实生产预读代码的多线程主机测试覆盖 240 行顺序、周期读延迟、断供、文件失败、关闭等待生产者结束后方可复用内存；三板配置 TX 状态机测试通过，双板构建及完整离线回归通过。dev.25 已仅刷 M5 应用分区并校验通过。#3 连续两轮无发射 probe 均完整 463 帧、100%，分别耗时 37042/37044 ms；最大编码 4714/5082 µs，音频线程最大取缓存行耗时 48/317 µs，最大超时 5277/4867 µs，无丢帧。这里的取行耗时是缓存获取时间，不再代表后台物理 SD 读耗时。已请求用户从硬件相册做实际收图验证，尚未宣称实际链路验收完成。GitHub 和公网刷写页均未更新；小智仅完成同版本构建，未刷机。
